# Железо — v4 (редизайн навигации и экранов)

Data → State → Core → Components → Screens → Layout — архитектура не менялась.
Открой `index.html`, сборка не нужна.

## Что изменилось в этой версии

### 1. Шрифты — теперь только локальные

Убрана загрузка Google Fonts. `css/00-tokens.css` подключает шрифт через
`@font-face` из `assets/fonts/`. **Положи туда следующие файлы:**

```
assets/fonts/Inter-Regular.woff2   (вес 400)
assets/fonts/Inter-Medium.woff2    (вес 500)
assets/fonts/Inter-SemiBold.woff2  (вес 600)
```

Если файлов ещё нет — приложение продолжит работать и просто использует
системный шрифт (fallback уже прописан), так что ничего не сломается,
пока файлы не добавлены.

### 2. Исправлен баг с выпадающими списками

Причина была в `js/layout/shell.js`: свайп-карусель слушала `mousedown`/
`mouseup` на всём экране, чтобы менять экран. Открытие нативного `<select>`
иногда даёт `mousedown` и `mouseup` в разных координатах (браузер рисует
дропдаун поверх), и это интерпретировалось как свайп. Теперь свайп
игнорирует события, начавшиеся на `select/input/textarea/button/a/label`.

### 3. Нижняя навигация

Точки-индикатор и панель вкладок убраны. Вместо них — `.bottom-nav`:
2 иконки экрана слева, круглая кнопка ▶ «Начать тренировку» по центру,
2 иконки справа. Активная иконка увеличивается с анимацией (CSS
transition, класс `.nav-icon.active`). Кнопка ▶ вызывает существующий
`App.Screens.TrainingSections.today.startSession()` с любого экрана.

### 4. Главная

Виджет с цифрами (вес/сон/ккал/шаги) заменён на графики: Вес, Сон,
Калории и новый график Шаги. Графики убраны с экрана «Здоровье».

### 5. Прогресс

Клик по «Топ прогресс» открывает полноэкранную модалку со всем прогрессом.
Внутри — иконки-переключатели типа отображения (полоска/кольцо/проценты)
и слайдер List/Grid вместо текстовых кнопок.

### 6. Тренировки — теперь 2 вкладки

- **Сегодня**: компактный календарь недели сверху (тап открывает полный
  календарь с выбором месяца/года — вся старая функциональность на месте,
  просто в модалке), список тренировки, кнопка начать, шестиугольная
  диаграмма нагрузки мышц (6 осей = 6 групп мышц, иконка на каждой) внизу.
- **График**: круглые аватары профилей (тап переключает, тап по активному —
  смена иконки из палитры), настройки формата/локации/группы, кнопка
  «Редактирование упражнений» (открывает полную базу упражнений в модалке),
  сгенерированный план недели.

### 7. Здоровье — теперь 2 вкладки

- **Дневник**: показатели дня одной строкой, блюда на сегодня (тап →
  блюда на неделю в модалке), сводка КБЖУ (цель/белки/жиры/углеводы/
  BMR/TDEE — расчёт через существующую формулу `Kbju.computeAll`),
  история показателей, быстрый импорт.
- **Рацион**: автоподбор (без изменений) → список блюд, переключатель
  «Блюда ↔ Конструктор блюд», в конструкторе — кнопка «Редактировать
  ингредиенты» (сворачиваемая панель), конструктор теперь строится
  вертикально (↓ вместо →), «Единицы отображения» — в самом низу.

Экран «Питание» полностью убран — все настройки цели/веса/возраста/
активности/КБЖУ перенесены в Настройки → Основное.

### 8. Настройки

«Основное» теперь содержит цель + полный блок расчёта питания (вес, рост,
возраст, активность, белок, жиры) — вместо отдельного экрана «Питание».
Экспорт/импорт остаётся в «Данные» (он и раньше не дублировался на
«Здоровье»).

### 9. Пасхалки

`onTitleClick` (уже существовавший в `_shell.js`) теперь передан во все
4 экрана — клик по заголовку любого раздела запускает ту же
`App.Core.EasterEgg.trigger()`, что и раньше была только на «Главной».

## Проверено

Полный прогон Playwright после каждого крупного изменения: сборка графика,
запуск тренировки через центральную кнопку (включая проверку, что клик по
фону НЕ закрывает активную тренировку), редактирование упражнений через
модалку, аватары профилей и смена иконки, сохранение показателей, блюда на
неделю, автоподбор рациона, конструктор блюд с вертикальной сборкой и
встроенным редактором ингредиентов, экспорт JSON, пасхалки на всех 4
разделах, и отдельно — воспроизведение исходного бага с `<select>`
(эмуляция mousedown/mouseup на разных координатах поверх дропдауна) для
подтверждения, что переход на другой экран больше не происходит.
Везде 0 ошибок в консоли.

## Совместимость с Tauri/Capacitor

Не изменилась — статический HTML/CSS/JS, `js/data/storage.js` остаётся
единственной точкой работы с localStorage.
